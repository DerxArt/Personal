Оскільки їх багато і кожен веде в різний cookbook — який приклад цікавить найбільше? Наприклад, з огляду на jev-hub (особистий асистент), могло б бути цікаво:

Ознайомився з трьома прикладами. Ось стислий розбір кожного:

## 1. Function calling (harness/routing) — трейдинг-асистент
Натуральна мова → виклик типізованої функції. Приклад: `"plot rolling correlation between nvda and spy for the past month"` → `rolling_correlation(symbol='NVDA', benchmark='SPY', window='1mo')` з `confidence 0.91`.

**Механіка:** кожен аргумент функції з фіксованим набором значень (`Literal["1mo", "3mo"]`) стає `Choice`-питанням. Один `Dispatcher` будує всі питання одразу (54 питання на команду для 10 функцій), в одному запиті приходять відповіді для *всіх* функцій, але код читає лише ту гілку, яку вибрав `__tool__`. `confidence` = найслабше судження в ланцюжку (не добуток), бо одна неправильна відповідь ламає весь виклик.

## 2. Guardrails для LLM — фільтр входу/виходу
Замість системного промпта (який джейлбрейк обходить) — окремий TypeSafe-запит на кожне повідомлення: 4 `Noul` (jailbreak, шкідливий запит, медична порада, самопошкодження) + 1 `Score` (тяжкість шкоди). Код сам вирішує поріг:

```
jailbreak=0.74, severity=0.51
strict (review≥0.35, action≥0.70) -> block
permissive (review≥0.35, action≥0.85) -> review
```

Та сама відповідь моделі → різне рішення залежно від політики в коді. Гарний приклад "case sensitivity": `self_harm=0.96` веде не в блок, а в окремий `support`-шлях.

## 3. Intent routing — маршрутизація тікетів підтримки
`Choice` (intent: order_status/product_question/return_exchange/complaint) + `Score` (complexity) в одному запиті. Далі чистий код:

```python
if intent.confidence < 0.5:
    route_to_human_agent(ticket_id)
elif intent.choice == "order_status":
    handle_order_status(ticket_id)  # без LLM взагалі
elif intent.choice == "complaint":
    if complexity.score > 1 or complexity.confidence < 0.5:
        route_to_human_agent(ticket_id)
```

**Спільний патерн у всіх трьох**: TypeSafe ніколи сам не приймає рішення — він повертає ймовірність/впевненість, а пороги й гілки `if` завжди в коді застосунку. Це і є суть "System One" — швидке структуроване судження, а не генерація тексту.
