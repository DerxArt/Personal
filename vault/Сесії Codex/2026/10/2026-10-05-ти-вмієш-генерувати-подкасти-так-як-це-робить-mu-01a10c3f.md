# Ти вмієш генерувати подкасти так, як це робить Muse або Грокбот?

> Імпортовано з Codex. Лише текст розмови: виклики інструментів, виводи команд і приховані міркування не включено. Секрети замасковано.

## Артур

Ти вмієш генерувати подкасти так, як це робить Muse або Грокбот?

## Codex

Так — можу дослідити тему й підготувати подкаст: сценарій живої розмови кількох ведучих, структуру, жарти, переходи й підказки для озвучення. Muse, наприклад, може перетворювати нотатки на аудіоподкаст, а Grok Bot має процес для підготовки й озвучення епізоду ([Muse](https://newsroom.spotify.com/2026-09-23/spotify-meta-muse-agent/), [Grok Bot](https://grokbot.dev/marketplace/podcast-pipeline/)).

У цьому чаті можу точно створити сам сценарій; готовий аудіофайл залежить від доступних інструментів озвучення. Дай тему й бажану тривалість — зроблю пробний епізод.

## Артур

Не о самом подкасте. Звук, аудио.

## Codex

Понял. Ты спрашиваешь про готовое аудио с синтезированными голосами. Сейчас я не могу прямо в этом чате сгенерировать и прикрепить MP3 с диалогом ведущих, как Muse или Grok Bot. Могу подготовить текст и разметку для озвучки, но сам звук здесь не создам.

## Артур

Окей, де я можу це згенерувати? Може я це можу зробити через курсор, через Claude, через Manus? Ну, типу, ще якісь яйки. Хто може генерувати подкасти на основі скинутих матеріалів? Я просто хочу скинути свої нотатки, щоб воно повністю їх озвучило.

## Codex

Для твоєї задачі найкраще підійде **[ElevenLabs Studio](https://elevenlabs.io/docs/projects/audio-native)** — там є обидва потрібні режими:

- **Треба озвучити нотатки повністю, майже дослівно:** створи проєкт *Audiobook*, завантаж PDF, DOCX, TXT або EPUB, вибери голос і експортуй MP3 чи WAV.
- **Хочеш саме подкаст із двома ведучими:** вибери *Podcast / GenFM*. Він створить розмовний сценарій за матеріалами, тож може переказати й скоротити нотатки замість озвучення кожного рядка. Можна задати формат і тривалість. Українська підтримується для синтезу голосу. [Документація Studio](https://elevenlabs.io/docs/projects/audio-native) · [Мови TTS](https://elevenlabs.io/docs/overview/capabilities/text-to-speech)

Ще простіший варіант для розмовного огляду — **[NotebookLM](https://notebooklm.google.com/)**: завантажуєш джерела й генеруєш Audio Overview. Він обговорює та узагальнює матеріали, а не читає їх повністю дослівно. [Опис Google](https://blog.google/innovation-and-ai/products/notebooklm-beginner-tips/)

Тобто якщо хочеш **почути всі свої нотатки без пропусків — ElevenLabs Audiobook**. Якщо хочеш **подкаст за їхнім змістом — ElevenLabs GenFM або NotebookLM**. Cursor тут не потрібен; це радше середовище для коду, а не готовий сервіс для озвучення документів.

## Артур

Але в Lemon Labs там, короче, ліміти виходять не дуже. Тобто знаєш, ну, типу там виходить так, що там ліміти дуже жорсткі і мені цього не буде вистачать.

## Codex

Так, ElevenLabs часто рахує озвучення за символами, тож на великих нотатках ліміт швидко закінчується. Є два практичні шляхи:

- **Google Cloud Text-to-Speech** — оплата за використання, а не за фіксований пакет символів. Для стандартних голосів є квота 4 млн символів на місяць, далі вказана ціна — $4 за мільйон. Є український голос; якісніші HD-голоси тарифікуються окремо. Це добре для дослівного озвучення великих обсягів, але налаштування менш просте, ніж у ElevenLabs. [Тарифи](https://cloud.google.com/text-to-speech/pricing/) · [Українські голоси](https://cloud.google.com/text-to-speech/docs/voices)
- **Piper локально на комп’ютері** — без оплати за символи й хмарних квот, є українська модель. Потрібно трохи налаштувати, а голос звучить більш синтетично. [Моделі й мови Piper](https://github.com/WEBDIENSTE/rhasspy-piper/)

Для твого випадку я б почав із Google Cloud: він озвучить текст повністю, а в межах стандартної квоти можна обробити дуже багато нотаток. Claude чи Cursor самі по собі квоту синтезу не прибирають — якщо вони передають текст ElevenLabs, витрачаються ті самі кредити.

Можу допомогти налаштувати простий процес: кидаєш файли в папку — отримуєш аудіофайли.

## Codex

Так, можу підключити Google Cloud Text-to-Speech до локального скрипту й налаштувати його на довгі нотатки. В API є окремий асинхронний метод для довгого тексту: [synthesizeLongAudio](https://docs.cloud.google.com/text-to-speech/docs/reference/rest/v1/projects.locations/synthesizeLongAudio).

Для реального запуску потрібен твій Google Cloud проєкт із увімкненим Text-to-Speech і налаштованою авторизацією. Я не можу авторизувати твій акаунт замість тебе; ключі й токени в чат надсилати не треба — налаштуємо доступ локально. Якщо ти маєш на увазі підключення Google Cloud просто як вбудований сервіс у цей чат, такого конектора тут немає.

## Codex

Підготував локальний інструмент: [README з інструкціями](</C:/Users/derda/Downloads/Video/Personal/google-cloud-tts/README.md>) і [скрипт озвучення](</C:/Users/derda/Downloads/Video/Personal/google-cloud-tts/tts_long.py>). Він приймає TXT, Markdown, DOCX і PDF, ділить великі документи на частини й збирає їх в один WAV. Для довгого озвучення Google вимагає Cloud Storage bucket, куди тимчасово записується аудіо; API має ліміт близько 1 МБ тексту на запит і позначений як Preview. [Інструкція Google](https://docs.cloud.google.com/text-to-speech/docs/create-audio-text-long-audio-synthesis)

Тепер налаштуй хмарний доступ:

1. У [Google Cloud Console](https://console.cloud.google.com/projectcreate) створи проєкт і прив’яжи billing.
2. Увімкни в ньому **Cloud Text-to-Speech API** і створи приватний **Cloud Storage bucket**.
3. Дай своєму Google-акаунту доступ до bucket з ролями **Storage Object Creator** та **Storage Object Viewer**.
4. Встанови [Google Cloud CLI для Windows](https://cloud.google.com/sdk/docs/install), відкрий PowerShell і виконай:
   ```powershell
   gcloud init
   gcloud auth application-default login
   ```

Після цього запустимо озвучення так:

```powershell
cd "C:\Users\derda\Downloads\Video\Personal\google-cloud-tts"
py -m pip install -r requirements.txt
py .\tts_long.py "C:\шлях\до\твоїх-нот.docx" --project ID_ПРОЄКТУ --bucket НАЗВА_BUCKET
```

Коли створиш проєкт і bucket, надішли лише їхні **ID та назву** — не ключі й не токени. Далі підставимо їх і запустимо перший файл.
