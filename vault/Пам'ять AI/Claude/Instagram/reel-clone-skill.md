**Lessons from that run:**
- `analyze-reference.mjs` crashed on single-shot reels (`hstack` needs >= 2 inputs); fixed on 2026-09-25 (`null` filter for a 1-tile sheet).
- Don't assume the office-pov font (Instrument Serif, 118 px) for every reference: it was far too narrow here (357 vs 459 px). Measure baseline pitch + cap height + per-line ink widths first, then compare candidates side by side and as a red overlay on the reference frame. Cream/yellow background objects (lantern glow, candle flame, paper) pollute colour-mask extents: use tol <= 12-15 and exclude those columns, or the widths come out wildly wrong.
- Apify `instagram-reel-scraper` run summary can say "0 items" while the dataset holds the reel: always fetch the dataset before giving up.

**Why / key constraints learned:**
- The Drive connector (`search_files` with `parentId`) lists folders but `download_file_content` returns base64 only, useless for videos (the user's own footage folder holds an 887 MB MOV). Unauthenticated download of a private folder returns 401 / a sign-in page (verified on their reel-intro folder). So stage 2 needs the folder shared "Anyone with the link – Viewer" (script `fetch-drive.mjs`) or a local ZIP path. The folder-listing parser (`embeddedfolderview`) is unit-checked on sample HTML only, not on a live public folder; the HDR tone-map chain in `prepare-footage.mjs` is untested on real iPhone HLG footage.
- No Python on this machine: everything is Node + ffmpeg + the HyperFrames kit.
- Reference audio is reused untouched; on-camera speech references are out of scope (no lip-sync). Deliver a `_muted` copy so the user can attach the same sound in Instagram.
